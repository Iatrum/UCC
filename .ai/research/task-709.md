# Task 709 review research

- Next.js 16 Route Handlers export HTTP methods and accept Web Request or NextRequest objects. Dynamic route params are promises. The tests can call those exports directly with real NextRequest objects. [Route Handler API](https://nextjs.org/docs/app/api-reference/file-conventions/route) · [Next.js 16 upgrade guide](https://nextjs.org/docs/app/guides/upgrading/version-16)
- Medplum SDK and server versions are tracked separately in the repository. The invite test exercises the real SDK client and service and intercepts HTTP requests. The proxy-rule check reads the checked-in Traefik rule. [Medplum 5.2.8 release](https://github.com/medplum/medplum/releases/tag/v5.2.8) · [Medplum ProjectMembership](https://www.medplum.com/docs/api/fhir/medplum/projectmembership)
- FHIR R4 requires Observation.status. The lab route applies its own allowed subset before loading the order. Referral listing uses ServiceRequest subject and the app's clinic identifier. [FHIR Observation](https://hl7.org/fhir/R4/observation.html) · [FHIR ServiceRequest](https://hl7.org/fhir/R4/servicerequest.html) · [FHIR search](https://hl7.org/fhir/R4/search.html)
- The review covers server routes. React and DICOM were checked for context. [React 19 release](https://react.dev/blog/2024/12/05/react-19) · [DICOM PS3.18 Web Services](https://dicom.nema.org/medical/dicom/current/output/html/part18.html)
- Bun shares module state within a test process. Scoped spies restore the functions after each test. Unique fixture access tokens avoid reusing cached authorization across route cases. [Bun mocks](https://bun.com/docs/test/mocks)
