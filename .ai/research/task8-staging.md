## Exact repository pitfalls
`UCC_BASE_URL` affects Playwright and warmup; `MEDPLUM_URL` affects e2e FHIR helpers/seed. Application server uses MEDPLUM_BASE_URL and browser uses NEXT_PUBLIC_MEDPLUM_BASE_URL. Changing only one creates split-target tests. Admin spec explicitly requires localhost:3210/8113; containment script also enforces localhost:8113. Seed accepts only localhost/127.0.0.1. Do not remove guards or tunnel remote staging into these ports on this shared box. Global setup creates catalog/inventory fixtures; workflow signs and bills fake patients. The gate is destructive to its target and needs a preflight before even warmup/global setup. Clinic check currently validates Patient identifiers, counts Encounters; it is not an AccessPolicy proof. `build:ci` skips env validation. Root `test:e2e*` scripts have production-domain defaults and MUST NOT be used for staging.

Origin/dev documentation branch lacks portions of the ai-work harness and Task 4 receiver fix. These observations describe ai-work; target commit manifest must list required prerequisite fixes explicitly. Current local server image `latest` and SDK 5.1.13 do not attest server 5.2.8. No issue-specific workaround is claimed: observed code restrictions explain the runner design.

## Plan, self-critique and safer choice
Choose a separate instance + non-superAdmin clinical project + separate Firebase, fake-only artifacts and denied production egress. A cheap second project on a production server shares operator bypass and failure scope; a single environment variable could point writable tests at production. Safer future implementation: fail-closed manifest preflight, endpoint/project/credential attestation, disposable runner and explicit fixture provenance before writes. Do not modify guards now. No resources bought, credentials created or target contacted. See [plan](../plans/task8-staging.md).
