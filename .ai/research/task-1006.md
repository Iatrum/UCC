# Task 1006 research

The November 26 demo QA report recorded a staff 403 from the practitioner picker and a 500 from Uploaded Files. Both new appointment URLs render the same booking page. The picker called the admin directory helper, which queries ProjectMembership. Clinic staff already have access to PractitionerRole for their assigned organizations and Practitioner through the clinic account. Use the authenticated user's client, resolve the current Organization, and fetch only active practitioners referenced by that organization's active roles. Return IDs and display names. Load the two appointment lookups independently so a clinician failure leaves the patient picker usable while booking still requires a clinician and slot.

Uploaded Files GET reads DocumentReference metadata from Medplum. The route imported Firebase Admin at module load even though it needs Storage only for uploads and deletion. A local import with a fake malformed individual private key reproduced a module-load failure (app/invalid-credential). Missing bucket configuration alone did not reproduce it because the bucket getter is only used for writes. QA captured the status and generic client error, so the exact demo configuration error is unverified. Defer Storage initialization to operations that use it. Query using both the authorized patient and clinic identifiers, and return a generic retryable error when the metadata store fails.
