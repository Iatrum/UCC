# Task 701 review research

- Next.js 16 route handlers accept Web Request and Response types. NextRequest adds Next.js URL and cookie handling. Call the exported handlers with NextRequest, check status and JSON, and inspect writes at the Medplum boundary. [Next.js 16 upgrade guide](https://nextjs.org/docs/app/guides/upgrading/version-16) · [Route handler API](https://nextjs.org/docs/app/api-reference/file-conventions/route)
- Medplum search returns resources matching its query. FHIR R4 token searches support the system-and-code form used for clinic identifiers and patient identifiers. The app-side filtering in the registration service occurs after its admin-client queries return. The in-memory tests model token search and persistence. Dev server AccessPolicy enforcement requires a separate integration check. [Medplum 5.2.8 release](https://github.com/medplum/medplum/releases/tag/v5.2.8) · [Medplum search](https://www.medplum.com/docs/search/basic-search) · [FHIR R4 search](https://hl7.org/fhir/R4/search.html)
- FHIR R4 Encounter ties the triage visit to a Patient and Observation can reference the Encounter. UCC adds its own queue status extension. The cancelled Appointment remains a resource. [Encounter](https://hl7.org/fhir/R4/encounter.html) · [Observation](https://hl7.org/fhir/R4/observation.html) · [Appointment](https://hl7.org/fhir/R4/appointment.html)
- This review concerns server handlers and fake FHIR resources. React rendering and DICOMweb services are outside the changed paths. [React 19](https://react.dev/blog/2024/12/05/react-19) · [DICOM PS3.18](https://dicom.nema.org/medical/dicom/current/output/chtml/part18/PS3.18.html)
