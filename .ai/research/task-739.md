# Task 739 — Imaging billing and X-ray review

- Medplum 5.2.8 provides typed FHIR writes. Its SDK distinguishes ordinary create from conditional create. Device-backed X-ray uses conditional create for the clinical order. Its checkout line uses the draft entry ID in the Encounter billing extension. [Medplum 5.2.8](https://github.com/medplum/medplum/releases/tag/v5.2.8) · [SDK conditional create](https://www.medplum.com/docs/sdk/core.medplumclient.createresourceifnoneexist)
- Next.js 16 Route Handlers process the Sign requests. React 19 refs provide the composer’s synchronous submit guard. The route still needs to handle resubmission after a response is lost. [Next.js 16 Route Handlers](https://nextjs.org/docs/app/getting-started/route-handlers) · [React useRef](https://react.dev/reference/react/useRef)
- FHIR R4 Procedure supports business identifiers. Its `preparation` status means the core event is yet to start. The ServiceRequest holds the order. [Procedure](https://hl7.org/fhir/R4/procedure.html) · [EventStatus](https://hl7.org/fhir/R4/valueset-event-status.html) · [ServiceRequest](https://hl7.org/fhir/R4/servicerequest.html)
- DICOM Modality Worklist communicates scheduled procedure steps to a modality. The device workflow is gated by the clinic’s PACS module. Generic catalog imaging follows the existing non-device order flow. [DICOM PS3.4 K.6](https://dicom.nema.org/medical/dicom/current/output/chtml/part04/sect_K.6.html)
- Task 704 is an ancestor of the reviewed `dev` base. Its status fix applies to both Procedure write paths. Task 738’s browser evidence covers one initial Sign, checkout and payment. Reading the write and read-back paths revealed a retry gap. The generic imaging line sent a catalog ID, which the FHIR persistence path discarded. The orders route compared the incoming catalog ID with the reloaded line’s display name. [Task 738 evidence](task-738.md) · [PR #342](https://github.com/Iatrum/UCC/pull/342)
