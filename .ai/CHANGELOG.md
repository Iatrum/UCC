## 2026-10-31 Task 6b – "Too many attempts" no longer shown as "wrong password"
- **What changed:** When Medplum blocks sign-in for a minute (5 tries per IP per minute), the login page now says "Too many sign-in attempts. Please wait about N seconds and try again." instead of "Incorrect email or password". If Medplum is down or answers 5xx it says the sign-in server is busy/unavailable. A real wrong password still shows the same generic message (no hint whether the email exists). The API now returns 429 + `Retry-After` for this case.
- **Why:** Medplum rate limits /auth/login and answers 429 with a `RateLimit: …;t=<secs>` header (medplum.com/docs/rate-limits, checked locally); RFC 6585/9110 for 429 + Retry-After.
- **Please test:** on the login page type a wrong password 6 times quickly -> the 6th shows "Too many sign-in attempts…". Wait a minute -> normal sign-in works.

## 2026-11-04/05 — Task 10: simulated analyser, result bridge, Lab tab pending tests
A new `scripts/poct/sim-analyser.ts` tool can stand in for a real POCT analyser during development: it keeps a test Device's "online" heartbeat going (or lets it go offline), and sends realistic HL7 (ORU^R01) or ASTM (E1394) result messages for a signed POCT order. Those messages are parsed and turned into the same lab result records doctors already see, by a new bridge (`lib/poct/analyser-bot.ts`) written in the shape of a Medplum `Bot` so it can become a real one later, reached today through a new `POST /api/labs/receive/message` endpoint (same device-key check as the existing lab result endpoint). The Lab tab (Labs & Imaging) now also shows POCT tests that are still waiting on a result, not just finished ones, so a doctor can see "Glucose — pending" before the analyser answers. No manual result entry was added anywhere — results only ever arrive through this message bridge, the same as the existing lab endpoint. While testing this, also fixed a bug found in the existing `/poct` worklist and the Lab tab's own result lookups: once a clinic or patient has more than 20 lab results or POCT orders, some patient names/results were silently dropped because a database search had no explicit limit (Medplum's default is 20). All four affected lookups now ask for up to 200.
**Why:** FHIR R4 Observation/DiagnosticReport (unchanged shape, reused); HL7 v2.5.1 and ASTM E1394-97 are the two message formats real lab analysers commonly speak. Medplum Bots need a server setting (`vmContextBotsEnabled`) that is not turned on for this shared box, so the bridge logic is written ready to become a real Bot but is not deployed as one yet — see `.ai/progress-task10.md` for the full reasoning.
**Please test:** `bun scripts/poct/sim-analyser.ts device demo glucose` then `heartbeat <deviceId> --once`, order a Glucose POCT test from a patient's Treatment tab and Sign, then `bun scripts/poct/sim-analyser.ts send-result <serviceRequestId> --code 14743-9 --name "Glucose (capillary)" --value 6.8 --unit mmol/L --interpretation high` — the patient's Lab tab should show the pending test before this, and the result with a "high" flag after.
