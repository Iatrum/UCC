# Task 1008 research

The two QA commits on the branch follow origin/dev at `c1d602e`. QA evidence comes from the November 26 round-two report, bugs and summary. The demo and branch can differ.

- The normal check-in form posts to `/api/triage`. The triage writer reuses a recent Encounter based on date alone, so it can reopen checkout's completed visit. Consultation and triage are separate Encounters. Use a clinic-checked visit association and keep the existing status mapping. FHIR R4 defines [Encounter.partOf, reasonCode and finished status](https://hl7.org/fhir/R4/encounter.html).
- Queue numbers currently come from the active table index. Use the order of today's visit Encounters before filtering completed visits; no counter write is needed to retain completed numbers.
- Registration already submits allergies. The AllergyIntolerance writer supplies neither clinic identifier nor ownership, while clinic staff fetch history under their own AccessPolicy. FHIR R4 defines [AllergyIntolerance.identifier and patient](https://hl7.org/fhir/R4/allergyintolerance.html). The [Medplum SDK search contract](https://www.medplum.com/docs/sdk/core.medplumclient.searchresources) accepts FHIR search parameters. [Medplum updateResource](https://www.medplum.com/docs/sdk/core.medplumclient.updateresource) supports request options.
- A subscription is an optional transport. Return an empty successful response for polling fallback under the existing clinic authorization and module gates. [Next.js 16 Route Handlers](https://nextjs.org/docs/app/getting-started/route-handlers) support the Web Response API.
- Order-composer optimistic writes already synchronously publish to a ref and serialize fetches. Reuse that latest value for repeated clicks and guard optimistic state while a newer write is pending. [React useState](https://react.dev/reference/react/useState#updating-state-based-on-the-previous-state) documents state snapshots and queued updates.
- Registration, triage and consultation already call Radix success notifications on this branch. Use the Sonner instance already mounted in the shared authenticated layout for these four observable workflow milestones.

For a local run, set `UCC_BASE_URL` to the loopback app and supply `e2e/.secrets/pw` (or the existing `UCC_USER` and `UCC_PASSWORD` environment variables). For the clinic demo, set `EMR_CLINIC_URL` and provide `e2e/.secrets/demo-login.env` or the host's runtime demo credential file. The config runs only the synthetic clinic journey, without the larger suite's shared seeding or stored sessions. ```sh
timeout --kill-after=10s 5m node_modules/.bin/playwright test --config e2e/playwright.task1008.config.ts
