# UCC live-demo QA root causes — 26 November 2026

Evidence comes from the round-two REPORT.md, bugs.json and summary.json, and from `git blame`, `git log -S` and first-parent merge history on the QA branch. The checkout is shallow. For lines blamed on boundary commit `6b0f3ca` ([#132](https://github.com/Iatrum/UCC/pull/132)), “present by” denotes the earliest locally attributable version. The merge title alone does not establish the original author or feature PR. The demo’s app version and exception telemetry were unavailable for this analysis.

## Systemic reasons

- GitHub’s CI workflow runs lint and a build. It does not run Bun tests or the authenticated Playwright workflow. Manual gates and mocked tests provided coverage for individual features, with different acceptance signals from the live demo.
- A successful API write was often taken as successful user feedback. Missing toasts, stale queue rows and mappings between two valid resources all survive isolated endpoint assertions.
- Real staff access, clinic account inheritance, an optional transport, and Firebase metadata listing depend on runtime configuration. Admin fixture reads, happy-path mocks and the demo deployment can all exercise different permissions or infrastructure.
- Fix rounds targeted individual regressions, including retry suppression for subscription 503 and queue pagination. The checks for those fixes accepted the remaining symptom or ended before the next clinic action.
