## Official source checked before implementation

- Medplum [5.2.8 Login definition](https://github.com/medplum/medplum/blob/v5.2.8/packages/docs/static/data/medplumDefinitions/login.json) and [5.2.15 definition](https://github.com/medplum/medplum/blob/v5.2.15/packages/docs/static/data/medplumDefinitions/login.json): both enumerate `user`, `code`, `cookie` search parameters. `revoked` is boolean resource data, not searchable. Search by user, follow every next link, then filter `revoked !== true` locally. Missing and false values both require revocation.
- Medplum [5.2.8 OAuth utils](https://github.com/medplum/medplum/blob/v5.2.8/packages/server/src/oauth/utils.ts): `revokeLogin` updates the original Login with `revoked:true`; `getLoginForAccessToken` reads the Login and rejects revoked/missing membership. `includeRefreshToken` requires `offline_access` (or configured client refresh grant); plain `openid` does not guarantee a refresh token. The fake verification login therefore requests `openid offline_access`. Operator login requests only `openid`.
- Medplum [5.2.8 token handler](https://github.com/medplum/medplum/blob/v5.2.8/packages/server/src/oauth/token.ts): refresh rejects revoked Login with OAuth `invalid_grant`; refresh rotates its secret. The helper first proves a valid refresh and retains the returned refresh token for the after-revocation probe. Testing an already-invalid refresh token would be vacuous.
- Medplum [5.2.8 login handler](https://github.com/medplum/medplum/blob/v5.2.8/packages/server/src/auth/login.ts): `projectId`, `scope`, S256 PKCE challenge and password login are supported. This helper deliberately requires a single dedicated operator project; MFA/ambiguous membership login responses fail closed, without printing the body. Sites requiring interactive MFA must have the maintainer provide a separately reviewed interactive flow; do not disable MFA.
- Medplum [5.2.15 OAuth utils](https://github.com/medplum/medplum/blob/v5.2.15/packages/server/src/oauth/utils.ts) checks revoked Login during access-token authentication too. Tagged source establishes an expected behavior, not a completed runtime proof.
- [FHIR R4 HTTP update/concurrency](https://hl7.org/fhir/R4/http.html#concurrency): version-aware updates use `If-Match: W/"<versionId>"`; stale updates may fail with 412. Preserve the returned Login fields and change only `revoked`. A failed page, wrong User, missing version, malformed boolean, duplicate record or unsafe next URL prevents the initial writes.
- [Next.js memory guidance](https://nextjs.org/docs/app/guides/memory-usage) and [React rules](https://react.dev/reference/rules) checked for repository constraints; no Next server, React/composer, UI, navigation, Firebase or DICOM integration changes are needed. DICOM is outside this session-administration fix; no DICOM API is introduced or assumed.
