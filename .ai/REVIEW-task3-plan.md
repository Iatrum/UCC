- **MAJOR — Incorrect route assumption.** Adding the error string preserves existing response behavior: GET returns `200` with an empty plan; POST/DELETE return `503`, `success:false`, `persistenceAvailable:false`. Step 1 incorrectly promises `200` for all three. The composer already handles the unavailable flag before checking HTTP status, so changing response contracts is unnecessary.
- **MAJOR — Non-persisted mode still claims autosave.** `persistenceDisabled` initializes to `!persistDrafts`. Gating the local-only message on `persistDrafts === true` leaves the default mode displaying “All changes autosaved” despite making no persistence requests.
- **MAJOR — Failure tracking misses deletion.** There are separate rollback paths in `persistEntry` and `removeEntry`. Setting `lastSaveFailed` only in “the catch that rolls back” risks leaving failed deletes reporting success. Both mutation paths need explicit failure/reset behavior.
- **MAJOR — Hydration failures remain misleading.** A genuine GET failure falls back to `initialEntries` without disabling persistence or recording failure. With no pending saves, the proposed footer still says “All changes autosaved,” although the stored draft could not be loaded.
- **MAJOR — Concurrent responses can still discard retained items.** Successful POST/DELETE responses replace the entire local plan. If one in-flight request disables persistence while another succeeds, that success can overwrite locally retained changes. The plan’s retention claim needs this case checked.
- **MINOR — Local-only copy overpromises retention.** “It is kept until you Sign” suggests guaranteed survival until signing, but the shown implementation holds entries in component state; refresh, unmount, or hydration reruns can replace them. State plainly that the draft is only on the current screen and is not saved to the server.
