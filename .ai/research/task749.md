# Task 749 research

- [Medplum 5.2.8 release](https://github.com/medplum/medplum/releases/tag/v5.2.8), [Medplum DocumentReference](https://www.medplum.com/docs/api/fhir/resources/documentreference), and [FHIR R4 DocumentReference](https://hl7.org/fhir/R4/documentreference.html). DocumentReference indexes attachment content and can point to a PDF or another format. The reviewed component renders clinic templates to HTML in an iframe and uses browser printing for PDF output. The review requires no Medplum SDK, FHIR resource, or storage changes.
- [Next.js 16 upgrade guide](https://nextjs.org/docs/app/guides/upgrading/version-16) and [App Router loading convention](https://nextjs.org/docs/app/api-reference/file-conventions/loading). Route loading covers navigation. The existing patient document dialog handles its own asynchronous client action.
- [React Effects and out-of-order responses](https://react.dev/reference/react/useEffect#fetching-data-with-effects). A completed request can arrive after a newer request. Ensure only the current viewer request can apply its HTML, errors, and loading state.
- [WAI-ARIA 1.2 aria-busy](https://www.w3.org/TR/wai-aria-1.2/#aria-busy) and [status](https://www.w3.org/TR/wai-aria-1.2/#status). A busy region can defer descendant announcements. Keep the polite status outside the busy preview and give the dialog an initial loading description.
- [DICOM PS3.18 Web Services](https://dicom.nema.org/Medical/dicom/2026a/output/html/part18.html). DICOMweb covers PACS imaging transactions. PDF printing here uses an HTML template; PACS ordering and viewer gates stay independent.
